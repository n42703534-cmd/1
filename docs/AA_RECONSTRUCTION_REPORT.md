# Adaptive Queue-Aware A* 重构与验证报告

日期：2026-07-21

## 结论先行

路由层重构已实现并通过 49 项回归测试，但当前不能宣称正式 AA 已获得可信的全负荷优势。
Mode 2/4 的共同物理执行层允许零速边产生无穷到达时间，导致 Improved 分别残留 197/797 人；
Mode 4 的 797 人全部滞留于 `Platform_L2_Z3_Wait -> Escalator_L2_down1` 的无穷在途记录。
因此 6000 秒不是 Improved 的 T100，680.5 秒也不能与历史约 1400/1300 秒基线直接比较。

## 本轮实现

- 正式入口恢复为 `AdaptiveQueueAwareAStar`；两个 Mesoscopic 方法仅保留为实验代码。
- 每个来源/真实到达时刻的自然批次独立运行完整图时间依赖 A*；没有固定批次大小、逐人对象、
  固定 K 候选路径或动态完整路径缓存。
- 边成本为共同物理旅行时间、预计资源等待和预计下游空间等待之和；后续 ETA 累计此前等待。
- 预测需求只含真实资源队列、未消费目标资源容量的确定在途到达、本轮此前已分配的整数事件。
- 批次按到达时间、来源组、节点、批次 ID 确定性处理；前批分配立即改变后批的预测状态。
- 排队批次可按统一收益 `R=(C_stay-C_switch)/(C_stay+C_switch)` 改路；普通中间节点及在途状态
  不重算路径。没有新增保持时间、EMA、软需求、浮点预留、校准系数或等待放大系数。
- 改路评估前从旧逻辑队列移除本批，决定后加入新队列尾部。该守恒修复把 Mode 2 前 100 秒
  A-B-A 从 81,567 次降至 23 次。
- Improved 规则未改；共同容量、速度、面积、人口、时间步、接收、回溢和整数移动未刻意改动。

## 尚未解决、且应先于新一轮调参处理的问题

1. 共同调度器不得把非有限旅行时间的移动写入在途队列；修复必须同时作用于 Improved 和 AA。
2. 修复后必须重新跑 Mode 1/2/4，确认历史基线为何从约 1400/1300 秒漂移到当前结果。
3. 空间预测的多出边出流聚合需要与实际选路约束一致，但不能靠经验系数修补。
4. 预测误差应按资源、来源和 ETA 分层，查明系统性低估来自服务扣除还是到达事件遗漏。
5. 批次 A* 性能需要等价的事件索引/启发式优化；禁止用动态完整路径缓存牺牲批次独立性。
