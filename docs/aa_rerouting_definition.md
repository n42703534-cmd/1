# AA 改路与防摆动定义

AA 只允许仍停留在明确选择阶段、尚未进入在途执行状态的批次重新评估路径。
已进入 `_transit_queue` 的批次继续执行已承诺边，不在途中瞬时改路。

对一个可改路批次，代码先评估保留当前路径的剩余成本 `C_stay`，再评估候选改路成本
`C_switch`。实际改路收益按当前实现定义为：

```text
R = (C_stay - C_switch) / C_stay
```

仅当以下条件同时成立时才切换路径：

- 候选路径有效；
- 下一跳不同；
- 候选路径仍在允许的选择范围内；
- `C_switch < C_stay`；
- `R > g_min`。

当前 Mode 4 使用 `g_min = 0.20`。该值是本项目场景下的防摆动阈值设置，不表述为
经过外部实验校准的通用参数。

同一轮内，批次会先从旧逻辑队列中退出，再加入新逻辑队列，以避免同一批人在两个资源队列中
重复计数。诊断中的 `reroute_count` 记录已接受的改路事件，
`effective_reroute_count` 记录改路批次在同一步实际获得移动容量的次数。
