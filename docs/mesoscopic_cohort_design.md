# 滚动时域介观批次单路径路由设计

更新时间：2026-07-21

## 1. 现有状态审计

### 节点人口

- `people`：节点总人数。
- `people_dict`：按线路汇总的人数。
- `source_group_dict`：按既有来源组汇总的人数。来源组包括列车、站台分区、站厅和换乘来源。
- 现有节点状态没有到达时间批次，也没有按批次保存路径承诺。

### 在途记录

`_transit_queue` 当前保存 `u`、`v`、`amount`、`depart_time`、`arrive_time`、`resource_id`、`line_shares` 和 `source_group_shares`。到达普通节点后，来源组会立即合并回节点的 `source_group_dict`。

### 旧路径状态

`_our_guidance_state` 按节点保存一条完整路径、下一跳和经验惯性状态。因此同一节点中的所有来源组使用同一个下一跳，不能表达不同自然批次的承诺。

### 物理执行顺序

旧顺序是：节点级路径提议 → `_integerize_moves`执行节点人数约束和共享资源容量 → `_apply_destination_receiving_limits`执行空间接收 → `_schedule_moves_as_transit`在获准总量中按来源组比例取人。来源身份拆分发生得过晚，不能把路径承诺精确赋给实际获准批次。

## 2. 新的自然批次

新批次由以下现有事实确定，不设置固定批次人数：

```text
来源组 × 到达当前节点的仿真时间 × 承诺状态
```

每个节点增加 `_mesoscopic_cohorts`。每条记录保存：

```text
cohort_id, source_group, arrival_time, amount,
committed_segment, segment_index, next_decision_node, committed
```

相同来源、相同到达时间和完全相同承诺状态才允许合并。不同承诺段不得合并。节点的 `people`、`people_dict` 和 `source_group_dict` 仍是共同物理层与评价层使用的守恒汇总。

## 3. 决策节点

显式 `routing_decision=True/False` 优先。没有显式属性时，只在至少两个可达出向分支通往不同关键资源、通道或出口时识别为决策节点；纯几何串联节点不作为决策节点。尚未承诺的初始/到达批次即使位于非决策节点，也允许进行一次启动规划，以获得通往下一个决策节点的路径段。

## 4. 路径段承诺

决策时在完整可达图上选择到任一出口的最小成本路径，但只保存当前位置到下一个决策节点的前缀。批次在中间节点只能继续承诺边；容量或空间不足时原地等待，不能改选。到达 `next_decision_node` 后清除旧承诺并重新规划。

承诺只赋给经过共享资源容量和下游接收限制后实际获准的整数人员。被拒绝人员仍位于原节点且保持原承诺状态；在决策节点提出的新路径尚未获准时不会形成承诺。

## 5. 正式算法

- `MesoscopicPhysicalTimeAStar`：完整图 A*，边成本仅为共同物理旅行时间。
- `MesoscopicCurrentQueueAwareAStar`：完整图 A*，边成本为共同物理旅行时间加进入资源前的当前真实队列等待 `Q_now / mu`。

两者共享完全相同的自然批次、决策节点、路径段承诺、整数容量和空间接收逻辑。旧节点级 AA 仅作为历史对照。

预测成本是时间依赖的，不能用静态边权普通 A* 代替。本轮只有在实现并验证时间依赖标签搜索后，才可把预测版列为实验结果。

## 6. 冻结的物理层

本设计不修改拓扑、人口、设施容量、速度、面积、出口能力、0.5 秒时间步、共享资源容量、容量单次消费、普通空间回溢、整数化或 ImprovedAStar 路由规则。
