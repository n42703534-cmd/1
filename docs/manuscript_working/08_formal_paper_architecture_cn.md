# 正式论文式框架：多线地铁换乘站应急疏散路径优化

> 状态：此文件为第二版正式框架。经进一步深读参考论文后，正式采用 `09_deep_reference_transfer_framework_cn.md` 作为第三版框架。

## 论文一句话

本文研究的不是“A* 算法改进本身”，而是**多线地铁换乘站在高负荷应急疏散中，由楼扶梯、闸机、通道和出口等受限设施服务队列引起的路径组织问题**。论文通过龙阳路站网络模型，将站内设施抽象为具有服务能力和排队状态的资源节点，在统一仿真执行层下比较改进 A* 基线与队列感知动态路径优化方法，并结合低负荷、高负荷、敏感性分析和 Pathfinder 对照评估其适用边界。

这句话决定全文重心：

```text
多线换乘站疏散问题
-> 受限设施服务队列
-> 到达时刻等待预测
-> 动态路径组织
-> 仿真验证与边界讨论
```

## 题目

建议题目：

**考虑设施服务队列的多线地铁换乘站应急疏散路径优化与仿真验证**

这个题目比“基于 AA* 的……”更稳。它先告诉读者研究对象是多线地铁换乘站疏散，再说明关键技术切入点是设施服务队列，最后说明文章类型是路径优化与仿真验证。

## 摘要结构

摘要应写成一段完整的小论文，不要写成方法清单。

第一句写场景：多线地铁换乘站在应急疏散中同时承受多线路客流汇入、站内空间封闭和设施服务能力受限的影响，楼扶梯、闸机、通道和出口容易形成连续瓶颈。

第二句写问题：传统基于静态距离或当前拥挤状态的路径规划方法，往往只能响应已经出现的拥堵，而难以反映乘客批次到达下游设施时形成的未来排队等待。

第三句写方法：本文构建一种考虑设施服务队列的时间依赖路径优化方法，将受限设施的预测队列长度和服务率转化为到达时刻等待代价，并纳入路径搜索过程。

第四句写实验：以龙阳路多线换乘站为案例，建立站内有向网络模型，并在 Mode 1 低负荷常规突发场景和 Mode 4 高负荷双向满载列车场景下，与 `PaperImprovedAStar` 基线在相同仿真执行层中比较。

第五句写结果：`[待最终结果冻结后填写：T95、T99、T100、累计静止人秒、关键设施 Jain、出口 Jain、运行时间。]`

第六句写边界：结果应表明或提示该方法可为高负荷换乘站瓶颈排队疏散组织提供决策支持，但其效果受设施容量参数、重路由阈值、图模型抽象和计算代价影响。

## 1 引言

引言的任务不是介绍算法，而是让读者相信：**多线换乘站疏散不是一个普通最短路问题，而是一个受设施服务队列支配的动态路径组织问题。**

### 1.1 多线换乘站应急疏散的现实压力

本节从城市轨道交通规模增长切入，使用中国城市轨道交通协会最新官方统计数据说明城市轨道交通和换乘站数量已经形成大规模网络化运行格局。然后把问题收束到多线换乘站：这类车站通常具有多线路、多站台、多站厅、多出入口和多方向客流叠加特征，一旦发生突发事件，乘客并不是从单一起点流向单一出口，而是多源同时进入受限设施链。

这一节应放入最新官方背景数字，但只作为问题背景，不要写成政策报告。

### 1.2 从几何最短路到设施服务链

这一节提出全文的核心观察：站内疏散路径的代价不只由距离决定，还由路径上连续设施的服务能力决定。乘客经过站台、楼扶梯、通道、闸机和出口时，每个环节都可能形成排队；一个下游设施的服务不足，会反向影响上游节点的等待和滞留。

这里要把“设施服务队列”引出来。建议用一个简洁例子：两条路径的几何距离相近，但其中一条路径通向未来会被大量乘客占用的闸机或楼梯。当前时刻看它不拥挤，乘客到达时却可能形成排队。

### 1.3 既有路径规划研究的不足

这一节不能说“没人研究地铁站疏散路径优化”。正确写法是：已有研究已经从微观仿真、多目标优化、引导策略、A* 改进、拥堵避让和设施容量等角度研究地铁站疏散，但许多方法更关注当前网络状态或整体目标函数，对“已分配乘客在未来到达受限设施时形成的服务队列”表达不足。

这里的缺口要窄而具体：

> 在高负荷换乘站疏散中，路径决策需要从“当前哪里拥挤”进一步转向“乘客到达时哪里会排队”。

### 1.4 本文研究内容

本节只交代本文做什么，不提前吹结果。

建议写成三点贡献：

1. 构建多线地铁换乘站疏散有向网络模型，将楼扶梯、闸机、通道和出口等设施表示为具有服务能力和队列状态的受限资源。
2. 提出考虑到达时刻预测等待的队列感知路径优化方法，在路径搜索中联合计算物理通行时间和受限设施等待代价。
3. 在龙阳路站 Mode 1 和 Mode 4 场景中，与 `PaperImprovedAStar` 基线、敏感性分析和 Pathfinder 对照共同验证方法效果与适用边界。

## 2 相关研究

相关研究要服务于本文缺口，不要按“作者 A 做了什么、作者 B 做了什么”堆文献。建议采用四段式。

### 2.1 地铁换乘站疏散行为与设施瓶颈

这一节讨论站内楼扶梯、通道、闸机、站台、站厅和出口对疏散过程的限制作用。重点不是复述每篇论文，而是说明多线换乘站的疏散具有“多源输入、串联设施、局部瓶颈传播”的特征。

这一节的结尾应自然导向本文：如果设施被视为连续服务链，那么疏散路径规划需要考虑服务能力和排队状态，而不仅是空间距离。

### 2.2 地铁站疏散仿真与路径优化

这一节讨论地铁站疏散路径规划已有方法，包括最短路、改进 A*、多目标优化、启发式算法、动态引导和微观仿真方法。写作重点是比较其路径代价的构成：距离、速度、密度、风险、出口容量、拥堵水平等。

这一节要把 Meng 等（2022）放到正确位置：它是本文 `PaperImprovedAStar` 基线和速度-密度参数复现的重要来源，但其研究对象是邮轮，不是龙阳路站实测参数来源。

### 2.3 容量约束、服务队列与高密度行走

这一节支撑本文的模型合理性。需要说明当人群密度升高或设施服务能力不足时，速度下降、接收受限和排队等待会共同影响疏散效率。速度-密度关系、高密度阈值、服务率和队列等待要分别定义。

这里要明确参数来源层级：

- 速度-密度模型和 3.0 人/m²阈值：文献基线复现参数；
- 龙阳路站设施宽度、数量、面积：站点模型或配置数据；
- 服务率换算：代码模型计算值；
- 排队区域深度、fallback 宽度、`gain_min`：模型假设或内部算法参数。

### 2.4 Pathfinder 与独立仿真验证

这一节为 Pathfinder 对照铺垫。Pathfinder 是微观行人仿真工具，可用于建立独立几何模型、检查路径分配趋势、拥堵位置和出口使用分布。但它不是现场实测数据，也不能作为图模型逐人轨迹的真值。

这一节的结论应是：本文用 Pathfinder 作为独立仿真参照，检验图模型的趋势合理性，而不是宣称现场验证。

## 4 队列感知动态路径优化方法

### 4.2 基线方法：`PaperImprovedAStar`

本节定义公平比较对象。`PaperImprovedAStar` 复现 Meng 等（2022）改进 A* 的核心代价结构，路径代价包含长度项、密度速度约束下的通行时间项和启发式项。它使用当前网络状态和共享执行层，但不引入 AA* 的到达时刻预测等待项。

这一节只讲基线，不顺手讲本文方法。

### 4.3 到达时刻服务队列预测

这是本文方法的关键小节。对于候选移动 \((u,v)\)，算法先估计乘客批次从 \(u\) 到 \(v\) 的物理通行时间 \(\tau_{uv}(t)\)，得到预计到达时刻：

```text
t_v = t + tau_uv(t)
```

若 \(v\) 是受限资源，则算法估计乘客到达 \(v\) 时的预测队列 \(Q_v^{pred}(t_v)\)，并将等待时间近似为：

```text
W_v(t_v) = Q_v^{pred}(t_v) / mu_v
```

这一节要强调：本文关注的不是“现在排不排队”，而是“到达时会不会排队”。

建议放：

**图 4 当前拥堵代价与到达时刻队列代价的区别**

### 4.4 `AdaptiveQueueAwareAStar`

本节把上面的预测等待嵌入路径搜索。候选边的动态代价可写为：

```text
c(u,v,t) = tau_uv(t) + I(v in R) * W_v(t_v)
```

其中 \(R\) 为受限资源集合。AA* 沿路径累积物理通行时间和预测等待时间，使搜索状态随预计到达时间更新。

本节建议写出伪代码：

**算法 1 队列感知时间依赖 A* 路径搜索**

伪代码应包含输入、候选边扩展、到达时间估计、资源队列预测、路径代价更新和路径输出。

### 4.5 动态重路由与路径稳定性

实际疏散过程中，如果每个时间步都根据微小代价差异改路，可能造成路径频繁切换。因此模型引入重路由收益阈值 `gain_min`。当前 Mode 4 配置中 `gain_min = 0.20`，它表示只有当新路径相对原路径具有足够收益时才触发切换。

必须写清楚：`gain_min` 是内部算法阈值，不是行人行为参数，也不是文献标定值。若最终结论依赖它，必须用敏感性分析支撑。

## 7 讨论

讨论章不是再讲一遍结果，而是解释结果为什么发生、说明边界在哪里。

### 7.1 为什么到达时刻队列比当前拥堵更关键

解释 AA* 的机制：在高负荷场景中，当前尚未拥挤的设施可能已经被大量上游乘客“预订”。如果路径代价只看当前状态，就会持续把后续乘客送向同一设施；如果看预计到达时刻队列，就能提前分流。

### 7.2 疏散效率、等待时间和路径长度的权衡

如果 AA* 减少静止等待但增加移动时间，这在机制上是合理的。它不是让所有乘客走最短路，而是让一部分乘客用更长的移动距离换取更少的瓶颈等待。

### 7.3 关键设施均衡与出口均衡可能不一致

这一段很重要。内部瓶颈均衡和最终出口均衡是两个层级的目标。减少楼梯、闸机或通道排队，不一定意味着出口人数更均匀。论文必须把这两个指标拆开解释。

### 7.4 与 Pathfinder 对照的关系

说明两类模型的互补关系：图模型适合快速评估路径组织策略和资源队列机制，Pathfinder 适合检验微观运动、局部拥堵和可视化趋势。两者一致时增强可信度，不一致时提供模型边界。

### 7.5 局限性

局限要具体：

- 设施容量来源仍需区分官方数据、模型抽取值和工程假设；
- 速度-密度关系来自文献基线复现，不是龙阳路站实测校准；
- `gain_min` 是内部阈值，需敏感性分析支撑；
- 图模型无法完全表达个体避碰、恐慌、逆行和群体行为；
- 实际部署需要实时客流感知和计算优化。

## 8 结论

结论应短，不要重新写一遍摘要。

建议四段式：

第一句：本文面向多线地铁换乘站应急疏散中的设施服务队列约束，构建了队列感知时间依赖路径优化方法。

第二句：`[待补最终结果]` 在 Mode 1 和 Mode 4 中，本文比较了 AA* 与 `PaperImprovedAStar` 在疏散效率、静止等待、线路清空、设施/出口均衡和计算代价上的差异。

第三句：`[根据最终结果选择]` 结果表明/提示，预测下游受限设施的到达时刻队列能够改善高负荷疏散中的瓶颈排队组织，但可能带来路径长度、出口均衡或计算时间方面的权衡。

第四句：未来研究应进一步结合实测客流、火灾烟气环境、微观行为仿真和实时控制需求，扩展到更复杂的多线枢纽疏散组织。
