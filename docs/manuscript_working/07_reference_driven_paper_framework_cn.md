# 参考论文启发下的中文论文框架设计

> 状态：此文件保留为分析备忘录。正式论文式框架以 `08_formal_paper_architecture_cn.md` 为准。

参考论文：Wei et al., "Dynamic firefighting route planning for efficient evacuation in complex subway stations: A deep learning-enhanced robust optimization approach", *Simulation Modelling Practice and Theory*, 146, 103223, 2026.

## 0. 先纠正一个可能的错误前提

这篇参考论文可以学习的是“复杂地铁站场景下，如何把仿真平台、网络模型、优化模型、求解流程和多指标验证串成一条证据链”。但不能直接迁移它的消防路径问题、BKA-GRU、鲁棒优化、IVYA、综合评价函数或图表结论。

原因是两篇论文的决策对象不同：

- 参考论文优化的是地铁站火灾场景下的消防人员救援/灭火路线，乘客疏散是评价消防策略影响的下层结果。
- 本文研究的是多线地铁换乘站内乘客应急疏散路径组织，核心变量是乘客批次、受限设施服务队列、到达时刻等待和路径分配。

因此，本文应借鉴其“组织逻辑”，而不是借鉴其“模型实体”。

## 1. 从参考论文提炼出的可借鉴组织方式

参考论文的主线可以概括为：

```text
现实安全问题
-> 文献缺口
-> 多源仿真数据
-> 网络/优化模型
-> 求解算法
-> 案例站验证
-> 多指标结果解释
-> 综合评价与边界
```

对应章节安排为：

| 参考论文章节 | 章节功能 | 对本文的启发 |
| --- | --- | --- |
| Introduction | 先说明地铁站封闭空间、高密度客流和火灾风险，再收束到动态消防路径规划问题 | 本文应先写多线换乘站高负荷疏散风险，再收束到“当前路径代价不能预见下游设施排队” |
| Related research | 按火灾数值模拟、行人疏散仿真、消防路径优化三类综述 | 本文应按地铁站疏散瓶颈、路径规划/引导、队列/容量约束、仿真验证四类组织，不按年份罗列 |
| The proposed model | 先放总流程图，再分解鲁棒优化模型、预测模型、评价指标 | 本文应先放技术路线图，再分解站点网络模型、共享仿真执行层、基线方法、AA* 队列预测代价、评价指标 |
| Solving method | 把“模型定义”和“求解过程”分章，避免公式与求解细节挤在一起 | 本文可把“AA* 路径代价定义”和“仿真中如何动态重路由/排队/溢流执行”分开写 |
| Case study | 先说明案例站选择，再说明 PyroSim/Pathfinder 场景，再按预测、求解、路径、疏散效果逐层验证 | 本文应先说明龙阳路站、多线换乘结构和客流场景，再按算法对比、瓶颈演化、Pathfinder 对照和敏感性分析逐层验证 |
| Conclusions | 总结方法、主要发现和适用边界 | 本文结论必须保留边界：图模型抽象、参数来源、计算代价、Pathfinder 不是现场实证 |

## 2. 本文建议采用的总论证句

建议把全文论证压成一句话：

> 面向多线地铁换乘站高负荷应急疏散中受限设施排队滞后反映的问题，本文构建基于设施服务队列预测的时间依赖路径优化方法，并在统一图模型仿真、低负荷与高负荷场景、敏感性分析和 Pathfinder 对照下评估其对疏散效率、瓶颈等待、负荷均衡和计算代价的影响。

这句话有三个优点：

1. 研究对象在前：多线地铁换乘站应急疏散。
2. 方法不是孤立算法：它是为解决“设施排队滞后反映”这个疏散问题服务。
3. 结果边界清楚：最终结论必须来自冻结后的 Mode 1、Mode 4、敏感性分析和 Pathfinder 对照。

## 3. 推荐题目

首选：

**考虑设施服务队列的多线地铁换乘站应急疏散仿真与路径优化**

备选：

1. 多线地铁换乘站高负荷疏散中的瓶颈排队演化与路径组织优化
2. 面向高负荷客流的地铁换乘站应急疏散过程仿真与引导优化
3. 多线地铁换乘站应急疏散过程仿真及瓶颈感知路径优化
4. 基于队列预测的多线地铁换乘站应急疏散路径优化研究

定稿判断：

- 如果最终结果重点展示瓶颈时序、关键设施排队和路径分流，题目 1 或备选 1 更强。
- 如果最终结果主要是整体指标对比，首选题目更稳。
- 不建议题名中出现 AA* 或 A*，因为本文重心应是地铁站疏散问题，不是算法命名本身。

## 4. 建议全文结构

### 摘要

建议按六句组织：

1. 多线地铁换乘站在应急疏散中面临高密度、多来源和受限设施排队约束。
2. 现有静态最短路或当前拥堵响应式路径引导，可能低估乘客到达下游瓶颈设施时的等待。
3. 本文构建一种考虑设施服务队列的时间依赖路径优化方法，在路径搜索中联合考虑物理通行时间和预测等待时间。
4. 以龙阳路站图模型为案例，设置 Mode 1 低负荷常规突发场景和 Mode 4 高负荷双向满载列车场景，并与 `PaperImprovedAStar` 在相同仿真执行层下比较。
5. `[待补：最终冻结结果，包括 T95/T99/T100、累计静止人秒、关键设施 Jain、出口 Jain、运行时间。]`
6. 说明该方法适合作为高负荷瓶颈排队管理的候选路径组织机制，但其应用仍受参数设定、计算代价和图模型抽象限制。

摘要里暂时不要写任何百分比提升。

### 2 相关工作

建议分 4 小节：

#### 2.1 地铁站与换乘站疏散行为及瓶颈

作用：说明楼扶梯、闸机、通道、站台和出口不是独立设施，而是串联服务系统。

可引用方向：

- 实尺地铁站疏散实验；
- 换乘站客流组织；
- 楼梯/通道拥挤和瓶颈排队；
- 多线换乘站或大型枢纽场景。

结尾要落到本文：本文把受限设施视为具有服务率和队列状态的资源节点。

#### 2.2 地铁站疏散路径规划与动态引导

作用：说明路径规划研究已经存在，本文不是从零发明“疏散路径优化”。

可引用方向：

- 多目标疏散路径规划；
- 引导人员/引导策略；
- 动态路径优化；
- A*、蚁群、遗传算法、强化学习等。

结尾要落到本文：本文关注的不是全局优化器更复杂，而是路径搜索时是否能预见下游服务队列。

#### 2.3 容量约束、排队与高密度行走模型

作用：给速度-密度关系、设施容量、排队等待和高密度阈值提供理论位置。

必须区分：

- 文献参数：Meng 等（2022）改进 A* 基线中的 Fruin 速度-密度关系和 3.0 人/m²高密度阈值；
- 模型设定：龙阳路站的宽度、闸机数量、面积、容量换算；
- 假设值：排队区域深度、fallback gate-bank 宽度、`gain_min`。

#### 2.4 疏散仿真工具与模型验证

作用：为 Pathfinder 对照定位。

写法边界：

- Pathfinder 可作为独立微观仿真对照或路径分配合理性检查；
- 不能写成真实现场验证；
- 不能要求图模型逐人复现 Pathfinder 轨迹，因为两者建模粒度不同。

#### 3.5 本文方法：`AdaptiveQueueAwareAStar`

这一节按“动机-机制-作用”写：

动机：

当前拥挤状态不能反映乘客到达下游设施时的未来队列。

机制：

对候选边 \((u,v)\)，估计到达时间 \(t_v\)，若 \(v\) 为受限资源，则计算预测队列 \(Q_v^{pred}(t_v)\)，并用 \(Q_v^{pred}/\mu_v\) 作为等待代价。

作用：

提前提高未来拥挤资源相关路径的代价，减少后续批次继续涌入同一瓶颈。

### 6 讨论

建议 5 个段落：

1. 核心发现：设施服务队列预测为何可能改善高负荷疏散尾部清空。
2. 机制解释：到达时刻队列比当前密度更适合描述下游瓶颈等待。
3. 权衡：更少静止等待可能伴随更长移动路径、更高计算成本或出口均衡下降。
4. 与既有研究关系：本文不是替代微观仿真，而是在图模型决策层加入可解释队列预测。
5. 局限与适用边界：参数来源、图模型抽象、Pathfinder 对照边界、实际部署需要实时数据与计算优化。

### 7 结论

建议 4 句：
