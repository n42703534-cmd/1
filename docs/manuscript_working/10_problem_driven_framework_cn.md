# 问题驱动版论文框架

参考论文：Wei et al., "Dynamic firefighting route planning for efficient evacuation in complex subway stations: A deep learning-enhanced robust optimization approach", *Simulation Modelling Practice and Theory*, 146, 103223, 2026.

本版状态：已被第 11 版替代。第 10 版虽然把论文从“AA* 与 Improved A* 的性能比较”转向了问题驱动，但“到达时刻瓶颈不可见”仍然偏抽象，且没有解释时间依赖路径搜索、共享容量执行、低负荷/高负荷验证分别服务什么研究问题。后续正式框架以 `11_arrival_load_argument_chain_cn.md` 为准。

## 1. 论文真正要讲的故事

推荐题目：

**多线地铁换乘站应急疏散中的到达时刻瓶颈预判与路径组织优化**

备选题目：

1. **面向到达时刻瓶颈预判的多线地铁换乘站应急疏散路径组织方法**
2. **高负荷多线地铁换乘站疏散中的下游瓶颈滞后显现与路径组织优化**
3. **考虑设施服务队列预判的多线地铁换乘站应急疏散路径分配方法**

最推荐第一个题目。它的重点在“多线地铁换乘站应急疏散”，创新点在“到达时刻瓶颈预判”，方法落点是“路径组织优化”，不会让读者误以为文章只是提出一个 A* 变体。

一句话论证：

> 本文针对高负荷多线换乘站疏散中仅依据几何距离或当前拥挤状态进行路径组织容易低估下游设施未来排队的问题，构建一种到达时刻瓶颈预判的疏散路径组织模型，将楼扶梯、闸机、通道和出口等受限设施抽象为共享服务资源，并通过低负荷、高负荷、敏感性分析和 Pathfinder 对照验证该模型对瓶颈滞留、疏散尾部时间和设施负荷分配的影响。

这里的中心不是“AA* 优于 Improved A*”。更准确的中心是：

```text
发现问题：当前状态看起来不拥挤的路径，可能在乘客到达时已经形成服务队列
怎么解决：把路径决策与设施服务队列执行耦合起来，按到达时刻预测瓶颈
方法是否有效：看它能否减少瓶颈排队、尾部疏散时间和负荷集中，而不是只看平均时间
如何证明：用机制诊断、模型验证、场景对比、敏感性和 Pathfinder 对照形成证据链
```

## 2. 需要重新定义的核心问题

旧版的问题定义过于像“路径规划算法改进”。这会导致论文一开始就被读者归类为普通算法应用，创新性不足。本文应当先定义一个与地铁换乘站场景直接相关的问题：

**到达时刻瓶颈不可见问题。**

在多线换乘站高负荷疏散中，乘客不是同时到达所有设施，而是以不同线路、站台、楼层和通道形成的自然客流批次逐步抵达楼扶梯、闸机和出口等受限设施。若路径组织只读取“当前时刻”的距离、密度或拥挤状态，则某条路径在决策时可能显示为低成本，但当后续乘客批次真正到达其下游设施时，前序批次已经在那里形成排队。此时，当前状态路径代价低估了未来服务等待，导致更多客流继续被导向同一瓶颈设施，形成滞后显现的拥堵累积。

这个问题比“算法更优”更适合作为论文创新入口，因为它直接来自地铁换乘站疏散场景：

- 多线换乘站存在多源客流、多层空间、共享通道和共享出口；
- 设施能力约束具有服务过程，而不是简单的几何边权；
- 高负荷下瓶颈不一定在决策时已经显性拥挤，而可能在乘客到达时才表现出来；
- 因此，疏散路径组织需要预测“到达时刻”的设施队列，而不是只读取“当前时刻”的设施状态。

需要注意：这是一个合理的研究假设，目前还不能在论文中写成“已被证明的普遍规律”。正式稿必须用基线仿真或典型设施时序图证明它在龙阳路站设定中确实出现。

## 3. 参考论文真正值得学习的地方

参考论文之所以显得自洽，不是因为它用了更多高级名词，而是因为它的章节顺序围绕一个清晰的问题闭合：

```text
消防预设路线在动态火灾环境与疏散干扰下可能失效
-> 构建火灾网络与乘客疏散网络的耦合模型
-> 用 BKA-GRU 预测关键节点通行时间
-> 用鲁棒优化处理时间不确定性
-> 用 PyroSim 和 Pathfinder 构造验证场景
-> 用路线成本、消防价值、火灾环境和疏散指标证明策略有效
```

对本文的迁移不应是复制“深度学习、鲁棒优化、IVYA、消防价值函数”，而是复制这种论证方式：

```text
当前路径组织在高负荷换乘站中看不见到达时刻瓶颈
-> 构建路径决策层与设施服务执行层的耦合模型
-> 预测乘客批次到达设施时的队列和等待时间
-> 用时间依赖路径搜索求解可行路径组织
-> 用共享容量执行保证排队和通行过程一致
-> 用低负荷、高负荷、敏感性和 Pathfinder 对照验证机制与效果
```

这条链条中的“自然批次、承诺到达、时间依赖 AA*”不是论文主线，而是解决上述问题的技术部件。论文里不能把它们写成读者必须先相信的一串名词，而要让读者看到每个部件解决了什么失败机制。

## 4. 方法中每个部件到底有什么用

旧版写法让人感觉“自然批次与承诺到达 -> 到达时刻设施队列预测 -> 时间依赖 AA* 路径搜索 -> 共享容量执行”只是堆流程。正确写法应当把每个部件和问题对应起来。

| 方法部件 | 不能这样写 | 应当这样写 | 它解决的问题 |
|---|---|---|---|
| 自然客流批次 | 把乘客分批进入算法 | 多线换乘站中客流不是均匀连续输入，而是由站台、换乘方向和列车到达形成批次化需求 | 避免把高负荷客流简化为同时决策的静态需求 |
| 承诺到达事件 | 记录已经规划的路径 | 当前批次一旦选择路径，就会在未来某时刻占用下游设施能力；后续批次决策必须看见这部分未来需求 | 让“尚未到达但已经确定会到达”的客流进入瓶颈预测 |
| 到达时刻队列预测 | 预测一个队列数 | 对候选路径上的受限设施，估计乘客抵达时已经存在的排队量和等待时间 | 把当前不可见的下游瓶颈转化为可计算路径代价 |
| 时间依赖路径搜索 | 用 AA* 搜索路径 | 候选路径代价随预计到达时刻变化，普通静态边权不能表达这种代价 | 在时间变化的设施等待条件下选择路径 |
| 共享容量执行 | 做仿真推进 | 多个路径选择会竞争同一楼扶梯、闸机或出口能力，执行层必须按服务率释放队列 | 保证模型没有用“虚假的无限容量”获得结果 |
| 稳定重路由 | 限制换路 | 只允许尚未进入下游路段的客流在收益足够时重分配 | 避免路径组织频繁振荡，符合疏散引导的可执行性 |

如果某个部件不能回到“到达时刻瓶颈不可见”这一问题，就不要把它放到论文主线里。

## 5. 建议的论文结构

### 1 引言

任务：让读者先理解“为什么多线地铁换乘站疏散不是普通最短路问题”。

写作逻辑：

1. 城市轨道交通规模扩大，多线换乘站承担高强度客流集散，应急疏散组织对站内安全运行重要。全国背景数字必须使用官方最新报告，不能沿用旧稿历史数字。
2. 多线换乘站疏散的关键困难不是单一路径距离，而是多源客流在楼扶梯、闸机、通道和出口等共享设施上的服务能力竞争。
3. 既有路径规划或疏散引导方法通常考虑距离、当前拥挤、风险或综合权重，但当前状态并不等于乘客到达设施时的状态。
4. 因此，本文提出“到达时刻瓶颈不可见问题”，并构建到达时刻瓶颈预判的路径组织模型。

引言最后一段的贡献不要写成“提出 AA* 算法”。建议写成：

- 提出多线换乘站疏散中的到达时刻瓶颈不可见问题，并给出面向设施服务过程的形式化描述；
- 构建路径决策层与设施服务执行层耦合的疏散路径组织模型；
- 设计基于承诺到达事件和设施服务队列预测的时间依赖路径组织方法；
- 以龙阳路站为案例，通过低负荷、高负荷、敏感性分析和 Pathfinder 对照评估模型对瓶颈滞留、尾部疏散和设施负荷分配的影响。

### 2 相关研究

这一节不要写成文献流水账，应当服务于缺口：

2.1 地铁站与换乘站疏散仿真研究  
说明已有研究如何处理站厅、站台、楼梯、闸机、出口和换乘通道，重点看多线换乘、复杂站型和高密度疏散。

2.2 疏散路径规划与动态引导方法  
总结最短路、A*、改进 A*、元启发式、多目标优化和动态引导方法。这里可以讨论 Meng et al. 的速度密度关系和高密度阈值，但必须说明其适用空间、单位和本文复现边界。

2.3 容量约束与排队行为建模  
重点讨论设施服务能力、瓶颈排队、通行时间预测、拥挤传播和 spillback。本文的缺口应落在“当前拥挤状态无法充分表达未来到达时刻的服务队列”。

2.4 本文定位  
明确本文不是提出通用最短路算法，也不是做全尺度火灾毒性仿真，而是研究多线换乘站高负荷应急疏散中的路径组织与设施服务队列耦合问题。

### 3 高负荷换乘疏散中的到达时刻瓶颈问题

这一节是新框架的关键。它对应参考论文中“先说明消防路线为什么会失效”的部分。没有这一节，论文就会继续像课程作业。

3.1 多线换乘站的设施服务链  
以龙阳路站为对象，把站台、站厅、通道、楼扶梯、闸机和出口组织成服务链。这里要区分三类数据：

- 官方或可核验数据：站型、线路、部分设施位置和公开资料中可确认的信息；
- 模型设定值：代码中明确写入的设施宽度、面积、服务率或容量计算规则；
- 假设值：无法从官方或实测来源确认、但为仿真闭合而设置的队列区域、等效宽度或补充参数。

3.2 当前状态路径代价的失真机制  
用一个小网络或龙阳路站典型设施示例说明：在决策时，某设施当前队列可能较短，但已承诺到达的前序客流会在后续时间占用其服务能力，因此后续批次到达时实际等待显著增加。这个图应当成为全文的“问题发现图”。

3.3 到达时刻瓶颈的形式化定义  
定义设施服务资源、当前队列、已承诺到达事件、服务率、到达时刻预测队列和预测等待时间。这里不需要把 AA* 放在标题里。

3.4 本文研究问题  
建议写成三个问题：

- RQ1：高负荷多线换乘站疏散中，当前状态路径组织是否会产生到达时刻瓶颈滞后显现？
- RQ2：引入到达时刻设施队列预判后，路径组织是否能减少关键设施排队和尾部疏散时间？
- RQ3：该方法在低负荷、高负荷、参数扰动和 Pathfinder 对照下是否保持稳定和可解释？

### 4 到达时刻瓶颈预判的疏散路径组织模型

这一节才进入方法。结构应当是“模型如何回应问题”，不是“算法流程介绍”。

4.1 网络与资源表示  
构建站内有向网络，将普通通行空间与受限服务设施区分开。节点和边属性包括几何长度、容量、面积、服务率、人数和候选出口等。龙阳路站设施参数的来源分类应在方法或实验设置中单独列表。

4.2 客流批次与承诺到达机制  
把乘客需求按线路、站台、方向或列车到达组织为自然批次。批次选择路径后，在其预计到达下游设施的时刻形成承诺到达事件，进入后续批次的队列预测。

4.3 到达时刻队列预测  
对候选路径中的受限设施，基于当前真实队列、已承诺到达、当前轮次前序批次分配和服务率，估计目标批次抵达时的预测队列和等待时间。这里要清楚说明预测队列不包括未决策的上游需求，也不是任意软预约窗口。

4.4 时间依赖路径搜索  
由于设施等待随预计到达时刻变化，路径代价不是静态边权。AA* 在本文中应被表述为时间依赖路径搜索的求解器，用于在动态预测代价下寻找路径，而不是论文贡献的全部。

4.5 共享容量执行与稳定重路由  
执行层按服务率释放各设施队列，并更新真实人数和空间密度。重路由只作用于尚未进入下游约束路段的客流，并需要满足最小收益阈值，避免路径引导频繁变化。

### 5 仿真场景与验证设计

这一节回答“怎么证明方法好”。不要把 Mode 1 和 Mode 4 叫成主实验模式，它们是低负荷与高负荷场景。

5.1 案例站与数据来源  
说明龙阳路站多线换乘属性、研究空间范围和设施抽象方式。必须用表格区分：

| 参数类别 | 示例 | 来源状态 | 论文写法 |
|---|---|---|---|
| 官方可核验数据 | 站名、线路、公开站型信息 | 待核对官网或正式资料 | 写明来源 |
| 代码模型设定 | 节点、边、面积、宽度、服务率、容量公式 | 已在代码中可追溯 | 写为模型设定 |
| 文献复现参数 | 速度密度关系、高密度阈值、权重 | 需核对原始文献 | 写为基线复现参数 |
| 假设参数 | 队列区等效面积、缺失宽度补足 | 暂无官方依据 | 写为仿真假设并做敏感性 |

5.2 疏散需求场景  
Mode 1 写为低负荷常规应急疏散场景，Mode 4 写为高负荷双向满载列车疏散场景。现阶段已知人数为 Mode 1 约 2187 人、Mode 4 约 17905 人，但正式稿需要以最终冻结结果为准。

5.3 对比方法  
Improved A* 作为文献基线复现；AA* 作为本文模型的求解实现；Pathfinder 作为微观疏散仿真对照。旧稿中的 AdaptiveSingleNextHop、ACO 和旧结果表不进入正式稿。

5.4 评价指标  
指标必须围绕问题设置，而不是围绕“谁快”设置：

- 疏散效率：T50、T80、T95、T99、T100、平均疏散时间；
- 瓶颈滞留：关键设施排队时长、累计排队人时、拥挤持续时间；
- 负荷分配：出口利用率、关键设施 Jain 指数、线路到出口分配矩阵；
- 执行稳定性：重路由次数、路径切换收益、是否出现振荡；
- 外部一致性：Pathfinder 中的疏散时间、拥堵区域和出口使用趋势。

### 6 结果与机制分析

这一节的顺序非常重要。不要第一张表就写“AA* 比 Improved A* 好”。建议按证据链排列。

6.1 基线下的到达时刻瓶颈诊断  
先证明问题存在。展示某些关键设施在决策时并不显著拥挤，但由于已承诺到达或前序客流持续输入，在目标批次到达时形成排队。建议图形：关键设施当前队列、已承诺到达、服务释放能力和实际队列的时间序列。

6.2 队列预测与路径组织机制验证  
使用小网络验证和回归测试说明：前序批次的路径选择会影响后续批次预测队列；未来到达改变路径选择；空间阻塞改变路径选择；不再依赖固定 K 候选路径或动态路径缓存。这里服务的是“模型正确性”，不是大规模效果。

6.3 低负荷场景结果  
低负荷场景不应强行写成巨大改进。它的作用是证明模型在常规负荷下不破坏基本疏散效率，且不会产生不必要的路径振荡。如果差异很小，也可以作为合理结果。

6.4 高负荷场景结果  
高负荷场景才是本文问题最可能出现的地方。这里比较不同方法下的尾部疏散时间、关键设施排队、出口负荷均衡和拥堵持续时间。若 AA* 在某些平均指标上不占优，但能降低关键瓶颈或尾部风险，也应按真实结果写出权衡。

6.5 机制解释  
解释效果从哪里来。建议至少包括：

- 线路到出口或线路到关键设施的分配变化；
- 关键楼扶梯、闸机或出口的队列时间序列；
- 高负荷后段尾部客流的清空过程；
- 某些路径被减少使用的原因是否与到达时刻预测队列一致。

6.6 敏感性分析  
敏感性分析不是附录装饰，而是回答模型边界。可以测试密度阈值、服务能力、重路由收益阈值、需求规模或速度密度参数扰动。结论应写成“在哪些条件下方法稳定，在哪些条件下收益减弱或失效”。

6.7 Pathfinder 对照  
Pathfinder 对照的作用不是证明代码仿真绝对真实，而是检验宏观或中观模型得到的拥堵区域、出口使用和疏散时间趋势是否与微观行人仿真具有一致性。若存在差异，应说明差异来源，例如人群行为模型、碰撞处理、局部绕行和空间表达方式不同。

### 7 讨论

讨论节不重复表格，应回答四件事：

1. 到达时刻瓶颈预判为什么在高负荷换乘站更重要；
2. 本文模型相比只看当前状态或静态路径代价的方法，真正改变了哪类路径组织决策；
3. 模型依赖哪些参数和假设，哪些参数来自文献复现，哪些来自代码设定，哪些仍是假设；
4. 本文不能声称什么，例如不能声称适用于所有地铁站、不能声称官方校准了所有设施容量、不能在最终结果冻结前声称某方法全面优越。

### 8 结论

结论只保留经过结果支撑的内容。建议结构：

1. 本文识别并形式化了多线换乘站高负荷疏散中的到达时刻瓶颈不可见问题；
2. 构建了路径决策与设施服务队列执行耦合的疏散路径组织模型；
3. 通过龙阳路站低负荷和高负荷场景、敏感性分析和 Pathfinder 对照评估了模型效果；
4. 说明适用边界与后续工作，例如设施参数实测校准、真实客流数据验证和火灾烟气耦合扩展。

## 7. 当前可写与暂不能写

已确认可以写：

- 研究对象是多线地铁换乘站应急疏散，案例站为龙阳路站；
- 论文范围包括低负荷和高负荷场景、敏感性分析、Pathfinder 对照；
- Improved A* 是文献基线复现，AA* 是本文路径组织模型的求解实现；

- 小网络验证可作为模型机制正确性的证据；
- 速度密度关系和高密度阈值属于文献复现参数，不能写成龙阳路站实测校准。

暂时不能写死：

- 全国城市轨道交通最新规模数字，必须到官方最新报告核对后再写；
- 龙阳路站全部设施容量均来自官方数据，这一点目前不能确认；
- AA* 在所有指标上优于 Improved A*，最终结果未冻结前不能写；
- Mode 4 是“最终主实验”，更准确说法是高负荷场景；
- Pathfinder 对照等同于真实疏散验证，这种表述不严谨。

## 8. 本版与旧版的根本区别

旧版：

```text
我有一个 AA* 方法
-> 与 Improved A* 比较
-> 看哪个指标更好
```

本版：

```text
高负荷多线换乘站存在到达时刻瓶颈不可见问题
-> 当前状态路径代价会低估未来服务等待
-> 构建路径决策与设施服务队列执行耦合模型
-> 用到达时刻队列预测组织路径

```

这才更接近参考论文的组织方式：不是先拿方法出来跑分，而是先说明现实疏散组织中什么会失效，再证明本文模型为什么正好解决这个失效点。
