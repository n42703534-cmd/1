本文拟题：

**考虑到达时刻设施队列的多线地铁换乘站应急疏散路径优化与仿真验证**

## 0. 上一版的问题

上一版框架已经避免了把论文写成“A* 算法论文”，但仍然没有充分吸收参考论文的真正组织方式。参考论文强的地方不是“章节多”或“用了 PyroSim + Pathfinder”，而是它把每个技术模块变成下一模块的输入，形成了一条连续证据链：

```text
场景参数与仿真数据
-> 节点通过时间预测
-> 鲁棒优化模型
-> 求解算法
-> 消防策略
-> 火灾环境与乘客疏散仿真
-> 距离-安全-拥堵综合评价
```

对应到你的研究，不能只写：

```text
地铁站网络
-> AA*
-> Mode 1/Mode 4 结果
```

这会显得像课程作业式的“算法跑分”。更严谨的写法应是：

```text
多线换乘站设施服务链
-> 乘客自然批次与承诺到达事件
-> 到达时刻设施队列预测
-> 时间依赖路径搜索
-> 共享容量执行与动态重路由
-> 低/高负荷仿真
-> 瓶颈排队、线路清空、负荷均衡、Pathfinder 对照
```

## 1. 参考论文真正值得学习的“论文机器”

### 1.1 它不是先讲算法，而是先定义“策略为什么会失效”

参考论文在引言中先说明：地铁站火灾中存在多点火源、烟气扩散、温度变化、通风影响、疏散通道拥堵和人员移动干扰。它的问题不是“找一条最短消防路线”，而是“预设消防路线在时变不确定火灾环境和疏散干扰下可能失效”。

这对本文的启发是：你的论文也不能从“我改进 A*”开头，而要从路径组织为什么失效开头。本文的问题应定义为：

> 在多线换乘站高负荷疏散中，当前时刻看似通畅的路径，可能在乘客批次到达下游楼扶梯、闸机、通道或出口时已经形成服务队列；因此，仅依赖几何距离或当前拥挤状态的路径规划会低估未来等待。

参考论文的问题核心是**环境不确定性导致预案失效**；你的问题核心是**到达时刻队列滞后导致当前路径代价失真**。

### 1.2 它构建的是耦合网络，不是单层路线图

参考论文构建了上层消防网络和下层乘客疏散网络：上层是火点和消防队任务，下层是闸机、楼梯、出口等疏散节点。两层网络通过火点到疏散节点的距离、客流量和消防价值函数耦合。这样做的意义是：消防路线不是孤立路线，而会影响乘客疏散环境和风险。

本文应借鉴这个“耦合”思想，但不能照搬上层火点网络。你的研究更适合构建：

```text
路径决策层
  乘客自然批次、当前位置、候选路径、预计到达时刻、路径承诺

服务执行层
  楼扶梯、闸机、通道、出口等受限设施，服务率、当前队列、接收容量、spillback

耦合关系
  决策层选择路径后写入承诺到达事件；
  服务执行层按容量释放队列并更新滞留；
  后续批次的路径搜索读取已更新的预测队列。
```

这个两层结构比“有向图模型”更像一篇论文的模型核心。它说明你的创新不是在图上跑 A*，而是把**路径决策**和**设施服务队列执行**耦合起来。

### 1.3 它的预测模块不是装饰，而是优化模型的输入

参考论文的 BKA-GRU 用来预测闸机、楼梯等节点通过时间，预测结果进入消防路线的行进时间计算。作者随后单独验证预测模型的收敛、拟合和误差，再把它用于优化模型。这使读者相信：优化模型中的时间输入不是拍脑袋来的。

本文没有 BKA-GRU，也不应该硬加深度学习。但你有对应的预测模块：**到达时刻设施队列预测**。它的输入不是训练数据，而是：

- 当前真实资源队列；
- 尚未消费资源容量的确定在途到达；
- 本轮此前已经完成路径分配的整数批次；
- 资源服务率；
- 预计到达时刻。

它的输出是：

- 预测队列 \(Q_v^{pred}(t_v)\)；
- 预测等待时间 \(W_v(t_v)=Q_v^{pred}(t_v)/\mu_v\)；
- 可选的预测空间等待或接收阻挡。

因此，本文也应像参考论文一样，单独设置“预测模块验证”：

- 小网络验证：第一批选择资源后，第二批是否能看到更新后的预测队列；
- 当前队列与未来队列对比：当前队列搜索和预测队列搜索是否产生不同路径；
- 空间阻塞验证：预测接收等待是否能改变路径；
- 回归测试：路径缓存、固定 K 候选路径等旧逻辑是否已排除。

本地已有 `aa_small_network_validation.csv`，可作为方法正确性验证的证据基础。

### 1.4 它把不确定性转化为可求解问题

参考论文用 box-intersection polyhedral uncertainty set 表达行进时间和消防时间不确定性，再通过 robust counterpart 和锥对偶转化为有限凸约束，最后用 Gurobi + IVYA 求解。关键不是“我们也要鲁棒优化”，而是它没有把不确定性停留在文字层面，而是把不确定性变成可计算、可求解、可验证的模型对象。

本文不能声称使用鲁棒优化，因为当前代码不是鲁棒优化模型。本文应把“时变未来状态”转化为可计算对象：

```text
当前队列 + 已承诺到达事件 - 到达前服务释放量
```

这就是你的“可计算未来状态”。它对应参考论文中的不确定集作用，但表达方式不同：

| 参考论文 | 本文 |
| --- | --- |
| 行进时间、消防时间存在不确定性 | 下游设施队列在乘客到达时发生变化 |
| 用不确定集描述可能波动 | 用承诺到达事件和服务率预测未来队列 |
| 通过 robust counterpart 变成可解约束 | 通过时间依赖 A* 标签搜索变成可搜索路径代价 |
| 用敏感性分析讨论权重与保守性 | 用 `gain_min`、容量、排队区域深度等敏感性分析讨论稳健性 |

### 1.5 它先验证求解过程，再验证策略结果

参考论文不是直接说“成本权衡策略最好”。它先验证 BKA-GRU 预测，再验证 IVYA 求解速度，再做权重敏感性，再比较三种策略的路线、环境、安全和疏散结果。也就是说，它的结果章有层级：

```text
预测模块可信
-> 求解模块有效
-> 权重变化可解释
-> 策略路线不同
-> 火灾环境不同
-> 疏散效果不同
-> 综合评价收束
```

本文结果章也应这样写：

```text
队列预测模块正确
-> 共享执行层公平
-> Mode 1 稳定性
-> Mode 4 高负荷效果
-> 关键设施排队机制
-> 线路清空和路径分配变化
-> 敏感性分析
-> Pathfinder 对照
```

这样读者才会觉得你不是只跑了两种算法，而是建立了一个可解释的疏散路径组织模型。

## 2. 本文应采用的核心模型表述

建议把全文核心模型命名为：

**路径决策-设施服务队列耦合模型**

英文可暂定为：

**a route-decision and facility-service queue coupling model**

不要过早把 AA* 当成全文主语。AA* 是该耦合模型中的路径搜索器，不是整篇论文的唯一对象。

### 2.1 路径决策层

路径决策层的基本对象是乘客自然批次。自然批次由来源组、到达当前节点时间和路径承诺状态定义。批次在决策节点进行路径选择；进入在途队列后不瞬时改路；到达下一个决策节点后重新评估路径。

这使模型区别于两类简单做法：

- 节点总人数统一选同一条路；
- 个体微观代理逐人连续避碰。

本文采用的是介观批次路径组织：它保留来源组和到达时间差异，又不声称复现每个个体行为。

### 2.2 设施服务队列层

设施服务队列层包含楼扶梯、闸机、通道和出口等受限资源。每个资源具有服务率 \(\mu_v\)、当前真实队列 \(Q_v(t)\)、排队存储区域和接收容量。当服务能力不足或下游空间饱和时，乘客在上游形成等待或 spillback。

这一层要严格区分：

- 真实资源队列：已经选择资源但尚未获得资源入口容量的人；
- 节点存量：物理位置上的人数；
- gate queue area：闸机排队区的空间存储；
- 诊断 backlog：不进入主路由队列定义的辅助量。

### 2.3 两层耦合机制

两层通过“承诺到达事件”耦合。某一批次选择路径后，其预计到达某个资源的时间和人数被记录为未来事件；后续批次搜索路径时，会把这些已承诺事件计入资源的未来队列。

这个机制可以写成：

```text
Q_pred(v, t_v)
= current resource queue
+ confirmed arrivals before t_v
- service released before t_v
```

这比单纯写 \(Q/\mu\) 更重要。\(Q/\mu\) 只是等待时间形式，真正的模型贡献是 \(Q\) 来自“未来承诺到达”的时间推进。

## 3. 正式论文框架

### 摘要

摘要应像参考论文一样形成“问题-方法-验证-结果-意义”的闭环。

第一句：多线地铁换乘站应急疏散受到多来源客流、封闭空间和受限设施服务能力共同影响，疏散效率往往取决于楼扶梯、闸机、通道和出口形成的连续服务链。

第二句：现有静态最短路或当前拥堵响应式路径规划方法，可能无法反映乘客批次到达下游设施时由已承诺客流形成的未来排队等待。

第三句：本文构建路径决策-设施服务队列耦合模型，并提出考虑到达时刻设施队列的时间依赖路径优化方法，将预测资源等待纳入候选路径代价。

第四句：以龙阳路多线换乘站为案例，建立介观有向网络模型，在 Mode 1 低负荷常规突发场景和 Mode 4 高负荷双向满载列车场景下，与 `PaperImprovedAStar` 基线在同一容量、密度、排队和 spillback 执行层中比较。

第五句：`[待最终结果冻结后填写：Mode 1、Mode 4、T95/T99/T100、累计静止人秒、线路清空、关键设施 Jain、出口 Jain、运行时间。]`

第六句：本文进一步通过敏感性分析和 Pathfinder 微观仿真对照讨论方法的稳健性、可解释机制和应用边界。

### 1 引言

#### 1.1 网络化城市轨道交通中的换乘站疏散压力

这一节从官方城市轨道交通规模数据进入，说明换乘站已经是城市轨道交通安全组织中的关键空间单元。写作重点不是宏观交通发展，而是引出“多线换乘站的应急疏散是网络化运营下的典型高风险场景”。

建议段落逻辑：

1. 官方数据说明城市轨道交通和换乘站规模；
2. 多线换乘站具有多来源客流、层级空间和多设施串联；
3. 突发情况下客流从站台、站厅和换乘通道同时进入出口系统；
4. 受限设施决定疏散过程，不是单一出口决定疏散过程。

#### 1.2 受限设施服务队列导致路径代价时变

这一节是全文问题的真正起点。要写出“当前代价”和“到达时刻代价”的区别。

参考论文说预设消防路线会被烟气、温度和人流扰动打破；本文应对应地说，当前最短或当前低拥堵路径会被未来到达的客流承诺打破。

建议核心句：

> 在高负荷疏散中，一个设施是否构成瓶颈，并不只取决于乘客决策时该设施的即时占用，而取决于乘客抵达该设施前已经被分配到该设施的未来到达量与服务释放量之间的关系。

#### 1.3 既有研究的能力与剩余缺口

这一节按三类文献组织：

1. 地铁站疏散仿真与行为研究已经揭示楼梯、闸机、通道和出口瓶颈；
2. 路径规划与动态引导研究已经引入距离、密度、风险或多目标优化；
3. 容量约束和队列模型已经说明服务设施对疏散效率的重要性。

然后指出剩余缺口：

> 对于多线换乘站高负荷疏散，仍需要一种在路径决策时显式利用已承诺未来到达、并将到达时刻服务队列反馈到路径代价中的方法。

#### 1.4 本文研究思路与贡献

贡献不要写成“提出一种改进 A*”。建议写成：

1. 提出路径决策-设施服务队列耦合建模框架，将多线换乘站内受限设施表示为具有服务率、队列状态和接收容量的资源节点；

### 4 到达时刻队列预测与时间依赖路径搜索

这一章对应参考论文的“预测模块 + 优化模型 + 求解方法”。不要把它写成单一算法小节。

#### 4.1 基线方法

定义 `PaperImprovedAStar`。它复现 Meng 等（2022）改进 A* 代价结构，使用同一物理执行层，但不使用本文的到达时刻队列预测。

#### 4.2 到达时刻设施队列预测模块

这是本文对应 BKA-GRU 的位置。写清楚输入、状态推进和输出：

```text
Input:
  current queue Q_v(t)
  confirmed arrivals to v before t_v
  current-round committed batches
  service rate mu_v
  estimated arrival time t_v

Output:
  predicted queue Q_v^{pred}(t_v)
  predicted waiting time W_v(t_v)
```

核心表达：

```text
Q_v^{pred}(t_v)
= max(0, Q_v(t) + A_v(t,t_v) - mu_v * (t_v - t))
```

如果正式公式需要更精细地按事件序列推进，可在正文中写事件递推，在附录给伪代码。

#### 4.3 时间依赖 AA* 路径代价

定义候选移动代价：

```text
c(u,v,t) = tau_uv(t) + I(v in R) W_v(t_v) + S_v(t_v)
```

其中 \(S_v(t_v)\) 可表示预测空间等待或接收阻挡项；如果最终公式不纳入空间等待，就不要写入主公式，可放入执行层说明。

强调搜索标签包含节点、累计预计时间、预计到达时刻和前驱，不能用静态边权普通 A* 替代。

#### 4.4 路径承诺、重路由与防摆动

定义 `gain_min`：

```text
R = (C_stay - C_switch) / C_stay
```

仅当候选路径有效、下一跳不同、成本更低且 \(R>g_{min}\) 时切换。当前 Mode 4 使用 `gain_min = 0.20`，这是内部防摆动阈值，不是行人行为参数。

### 7 讨论

#### 7.1 从“当前拥堵响应”到“到达时刻服务队列预测”

解释本文相对既有动态路径规划的机制差异：不是更复杂地惩罚当前拥堵，而是把已经承诺到达的未来需求纳入路径代价。

#### 7.2 为什么高负荷场景更能体现方法价值

低负荷下服务队列不明显，AA* 的预测优势可能有限；高负荷下多个线路客流同时到达受限设施，未来队列预测才会改变路径组织。

#### 7.3 负荷均衡不是单一指标

内部设施均衡和最终出口均衡必须分别讨论。AA* 可能改善楼梯/闸机等瓶颈均衡，却不一定改善出口人数均衡。

#### 7.4 与 Pathfinder 的互补关系

图模型适合做路径组织决策和队列机制分析，Pathfinder 适合做微观拥堵趋势和几何可视化对照。二者不是替代关系。

#### 7.5 局限性

具体局限：

- 速度-密度参数来自文献基线复现，不是龙阳路实测标定；
- 设施容量需要区分官方数据、模型抽取、代码换算和假设；
- `gain_min` 为内部阈值；
- 图模型无法表达个体避碰、恐慌、逆行和群体行为；
- 当前无火灾烟气场，因此不能写成火灾环境耦合疏散模型；
- 实际部署需要实时客流感知和计算优化。

### 8 结论

结论只写已被结果支持的内容。建议结构：

1. 本文提出路径决策-设施服务队列耦合模型和到达时刻队列感知路径优化方法；
2. `[待补最终结果]` 在 Mode 1 和 Mode 4 中报告效率、拥堵、均衡、计算代价和 Pathfinder 对照；
3. 结果表明/提示 `[按最终结果选择动词]` 到达时刻服务队列预测可改善高负荷多线换乘站疏散路径组织；
4. 方法仍受参数来源、图模型粒度、微观行为差异和实时计算条件限制。
