# 龙阳路论文重写蓝图（TUST 中文稿）

## 一、中心论点

多线换乘站的疏散路径决策不能只读取决策时刻的局部状态。多个客流批次在到达共享楼扶梯、通道和出口之前，其他已分配客流会改变设施队列；因此，需要在候选路径评价中把资源状态推进到乘客预计到达时刻。本文检验 AA* 能否借此压缩高分位至完全清空阶段的尾部并减少等待暴露，同时量化绕行和计算代价。

## 二、研究问题

### 主研究问题

在无火灾、建模设施均可用的多线换乘站疏散中，将当前队列、在途承诺流量与设施服务过程推进至预计到达时刻，能否改善共享瓶颈的等待暴露和 $T_{95}$–$T_{100}$ 尾部清空？

### 子问题

1. 相比 Improved A*，AA* 是否改变站级完成分布与各线路清空顺序？
2. 这种改变通过哪些共享设施和来源—出口流量重分配实现，并对应多少额外移动与计算代价？
3. 资源等待、到达时刻预测、空间接纳等待、时变多标签和密度暴露项各自贡献什么？
4. 将两组网络路径固定映射到 Pathfinder 后，AA* 与 Improved A* 的差异能否在连续空间微观运动中复现？Pathfinder Goto Any Exit 所代表的软件原生自主选出口会呈现怎样的平均效率—尾部清空取舍？
5. 待低负荷结果冻结后：上述差异是否随共享设施竞争强度改变？

## 三、正文结构与每节证据任务

### 1 引言

第一段从多线客流共享有限设施切入；第二段综述动态路径、节点排队和微观仿真的进展；第三段指出“决策时刻状态”与“预计到达时刻状态”的错位；第四段给出研究问题、方法和贡献。引言不展示 RQ 列表式海报图，也不预告“全面优于”。

### 2 文献基础与研究定位

2.1 地铁站设施网络与节点排队；2.2 动态疏散路径和时间依赖代价；2.3 微观仿真在优化方案执行检验中的角色；2.4 本文定位。这里需要把“算法规划”和“运动执行”分开，避免把 Pathfinder 当成算法真值。

### 3 方法

3.1 CAD 派生的多层设施—通道系统与资源映射；3.2 Improved A* 和 AA* 共用的物理加载层；3.3 到达时刻队列的事件推进；3.4 资源等待、批处理和空间接纳；3.5 密度暴露代价与时变多标签；3.6 路径映射到 Pathfinder 的实现。

### 4 案例与实验设计

4.1 龙阳路站体与 16 个最终出口；4.2 2,187 人基准需求及 17,905 人列车叠加需求；4.3 网络主比较；4.4 机制指标和人口守恒；4.5 单模块消融；4.6 Pathfinder 跨模型微观复现。低负荷和高负荷使用相同指标协议。

### 5 结果

5.1 站级完成分布和线路清空；5.2 等待—移动构成及出口/设施负荷；5.3 来源—出口重分配和关键瓶颈；5.4 消融机制；5.5 Pathfinder 高负荷微观复现；5.6 低—高负荷比较（待数据）。结果段每段遵循“结论句—图/表证据—机制解释”，不逐项报表。

### 6 讨论

6.1 到达时刻协调为何会产生“绕行换等待”；6.2 平均效率与尾部清空为何会分离；6.3 在批次级引导中的实施含义；6.4 仅保留与结论边界直接相关的简短说明。讨论不重复结果表。

### 7 结论

用三到四个结果句回答研究问题：站级尾部、机制来源、跨模型复现、计算取舍。低负荷未完成前不写其方向。

## 四、Pathfinder 小节的正式写法

### 方法表述

为检验网络路径分配在不同运动表征下是否保持相同的结果方向，本文将 Improved A* 与 AA* 生成的路径/出口分配映射到同一 Pathfinder 站体模型，并在 Steering 模式下执行连续空间微观运动。两组场景均包含 17,905 名乘客，`.geom` 文件的 SHA-256 完全一致。两组乘客姓名集合一致，因此其完成时间可做同名描述性配对；参数审计同时记录了少量 ID、房间、坐标和初始朝向差异，正文不将该配对解释为随机对照试验。

另设置 Pathfinder Goto Any Exit 场景作为软件原生自主选出口参照。其行为脚本为 `goto exit any`；Pathfinder 技术手册将内部路径规划描述为 Locally Quickest。该参照用于比较自主重规划与网络预分配路径的场景级完成分布，不称为 PF-LQ，也不与前两组做同名乘客配对。

### 结果表述

在高负荷 Pathfinder 运行中，AA* 映射方案相对 Improved A* 映射方案将平均完成时间从 435.5 s 降至 396.0 s，将 $T_{95}$ 从 1024.5 s 降至 985.1 s，将 $T_{100}$ 从 1414.6 s 降至 1298.3 s。17,905 名同名乘客中，10,073 名（56.3%）在 AA* 方案下更快；平均与中位完成时间差分别为 39.5 s 和 12.2 s。

Pathfinder Goto Any Exit 的平均完成时间为 362.5 s，低于两种预分配路径方案，但其 $T_{95}$ 和 $T_{100}$ 分别为 1034.1 s 和 1458.5 s，高于 AA* 映射方案。经验累计曲线与分位剖面因此显示，中段乘客的快速完成和最后残余乘客的清空是不同的性能维度：软件原生自主选出口更有利于平均效率，而 AA* 映射方案更早结束 $T_{95}$–$T_{100}$ 尾部。

## 五、消融小节的正式写法

完整 AA* 的高负荷网络运行得到 $T_{95}=889$ s、$T_{100}=1222$ s。去除资源队列等待代价后，二者分别增至 2634 s 和 3454 s，累计静止暴露增加 164.6%；该模块构成方法识别容量服务瓶颈的基础。保留资源等待但关闭到达时刻队列预测后，$T_{95}$ 与 $T_{100}$ 分别增至 1060 s 和 1427 s，累计静止暴露增加 45.2%，说明把队列推进至预计到达时刻提供了区别于当前状态代价的主要增益。

去除密度暴露项和将搜索改为单标签后，$T_{95}$ 均保持 889 s，但 $T_{100}$ 分别增至 1254 s 和 1251 s；它们的独立作用集中在最末端残余客流。去除规划层空间接纳等待后，当前高负荷汇总指标不变。这里应明确区分：物理执行层的有限接纳和溢回仍然开启；不变的是额外规划预测项，而不是空间容量本身没有作用。
